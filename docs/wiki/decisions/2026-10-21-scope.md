# 2026-10-21 — scope and sequencing

Decision recorded after reviewing `TODO` and the editor code at
`25adb9d` (branch `production`).

## Accepted scope

1. **Login UI** follows the user's saved light/dark setting. It must not rely on
   the operating-system `prefers-color-scheme` while the rest of the app uses
   `body[theme-mode]`.
2. **Share button** is a visible header action that copies the canonical
   `/diagrams/:id` URL. It does not change the access model.
3. **DBML editor** starts read-only. A user can enter an exclusive edit mode.
   While that mode is active, GUI editing is read-only for everyone, including
   the DBML editor. The lock is server-enforced with a lease.
4. **Circles** start as visual-only annotations (variant B+): a circle labelled
   `d`/`o`, optional double line for total specialization, and drag-created lines
   to table edges. They do not create or connect keys and do not affect SQL or
   DBML export.
5. **Field highlight bug** is deferred until a reliable reproduction exists.

## Sequencing rule

Worktrees isolate each milestone, but milestones are merged sequentially
(M1 → M2 → M3) because they share `Workspace.jsx`, `ControlPanel.jsx`,
`Editor.jsx`, i18n and document schema files.
